Who owns each boundary?

Agent control plane
Routes intent, coordinates model and agent work, records cost, and pauses for human review.
Integration layer
Connects approved APIs, data services, event systems, and existing applications.
Institutional controls
Owns the ontology, entitlements, data policy, approval authority, and retention rules.
Execution platform
A later destination for approved product and pricing workflows. This pilot does not execute there.

How proposals reach models, data, and controls

The model receives intent and catalog metadata. Governed tools handle source access, while policy services decide what the workflow may do.

Model connector

Governed model route

Gemini Flash or Claude receives intent and approved catalog metadata, then returns schema-constrained JSON.

  • Provider and model allowlist
  • Request-scoped or environment key
  • Keys and raw payloads are not stored
  • Model has no approval authority
Source connectors

Governed tools and APIs

Agents invoke purpose-built tools that enforce identity and scope before reaching a file share, database, or policy index.

  • Document retrieval API
  • Read-only servicing view
  • Policy retrieval with citations
  • No unrestricted network access
Control connectors

Authority and evidence systems

Identity, policy, review, ticketing, repositories, testing, and deployment remain explicit enterprise integrations.

  • User and agent identity
  • Approval and separation of duties
  • Evidence and cost records
  • SDLC change intake
OpenWiki and OKF can organize code knowledge and portable metadata. llms.txt helps an agent navigate documentation. Source authorization still belongs in the runtime connector.
